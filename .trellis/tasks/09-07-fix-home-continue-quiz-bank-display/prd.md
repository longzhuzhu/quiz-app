# 修复首页继续答题题库显示

## Goal

修复首页“继续上次答题”卡片在用户切换到另一个题库继续/开始答题后仍显示旧题库的问题，使该卡片始终指向用户最近实际活动的未完成答题会话。

## Confirmed Facts

- 首页 `frontend/src/views/HomeView.vue` 通过 `/quiz/history?page=1&per_page=100` 获取答题历史，并在前端选择第一个 `is_completed === false` 且 `mode !== 'wrong_practice'` 的会话作为“继续上次答题”。
- 后端 `backend/app/api/routes/quiz.py` 的 `/quiz/history` 当前按 `QuizSession.created_at.desc()` 排序。
- 用户继续一个较早创建的题库会话并提交答案时，`submit_answer` 只更新对应 `QuizAnswer.answered_at` 和会话统计，不会改变 `QuizSession.created_at`。
- 因此，“上次答题”当前语义实际是“最新创建的未完成会话”，不是“最近有答题活动的未完成会话”。

## Requirements

- 首页顶部“继续上次答题”按“最近有答题提交的未完成会话”定义；没有答题记录时按会话创建时间兜底。
- 如果未完成会话没有任何答题记录，则仍应按会话创建时间参与排序，避免新建未答会话丢失。
- 各题库列表中的每个题库“继续答题”入口仍应保留，每个题库只显示该题库最合适的未完成会话。
- 修复范围应保持最小，不引入新的前端状态缓存、复杂会话管理或数据库迁移，除非排查证明必须。

## Acceptance Criteria

- [x] 用户有多个未完成会话时，首页“继续上次答题”显示最近提交过答案的未完成会话的题库名称。
- [x] 用户新建一个未答题会话后，该会话可作为最近会话显示。
- [x] 错题练习 `wrong_practice` 不出现在首页“继续上次答题”卡片中。
- [x] 点击首页顶部“继续答题”进入的 session 与卡片显示的题库一致。
- [x] 现有答题历史、首页统计和题库列表继续可用，无明显回归。

## Out of Scope

- 不重做答题历史页面的交互设计。
- 不新增用户可配置的“继续答题”偏好。
- 不清理既有历史数据。
