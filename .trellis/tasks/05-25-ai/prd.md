# 实现题目 AI 产物预热

## Goal

提升答题过程中的翻译与 AI 解析响应体验：用户进入题目时，系统静默预先生成当前题和下一题的可缓存 AI 产物；用户之后点击“翻译”或“AI 解析”时，如果后台已完成生成，就复用现有题目缓存并立即展示。预热是机会性体验优化，不改变答题主流程，也不向用户暴露预热状态。

## Requirements

### 产品与用户体验

- 预热覆盖所有正式答题场景，包括顺序练习、随机练习、错题练习，以及后续新增的正式答题模式。
- 预热只在答题会话中触发；不覆盖题库管理、题目预览、导入复核、管理员查看等非答题场景。
- 预热过程对用户完全静默：不显示“预热中”“已预热”“预热失败”等状态。
- 点击“翻译”或“AI 解析”按钮时，保持现有交互与接口语义：已有缓存直接展示；没有缓存则同步生成并显示现有 loading。
- 预热未完成、失败、重复、已缓存、设置关闭等情况都不改变答题页交互。
- 前端进入题目时 fire-and-forget 调用预热接口，不等待响应，不阻塞答题、切题或提交答案。
- 前端对预热接口失败统一静默忽略；认证失效仍由全局 Axios 拦截器处理。

### 系统设置

- 在管理员系统设置页新增“答题设置”分组。
- 在“答题设置”分组中新增开关，文案为“是否启用答题预热”。
- 开关说明文字应说明：开启后，答题时会静默预先生成当前题和下一题的翻译与 AI 解析，以提升点击响应速度，可能增加 AI 调用成本。
- 开关是全局系统设置，默认开启。
- 新增独立接口：
  - `GET /api/settings/quiz`
  - `PUT /api/settings/quiz`
- 接口字段命名为 `quiz_ai_prewarm_enabled`，返回 boolean。
- 底层 `SystemSetting` key 使用同名字符串 `quiz_ai_prewarm_enabled`。
- `SystemSetting` 存储值使用字符串 `"true"` / `"false"`；读取时转换为 boolean，缺省默认 `true`。
- 普通答题页不额外读取系统设置；是否真正入队由后端预热接口作为可信边界判断。

### 预热 API

- 新增 `POST /api/ai/prewarm`。
- 请求体：

```json
{
  "session_id": 123,
  "question_ids": [10, 11]
}
```

- `question_ids` 由前端传入，通常为当前题与下一题。
- 后端通过 `X-Exam-Slug + 当前用户 + session_id` 校验请求属于当前考试项目内的合法答题会话。
- 后端必须校验每个 `question_id` 属于该答题会话和当前考试项目。
- 预热接口只返回粗粒度结果：

```json
{ "accepted": true }
```

或：

```json
{ "accepted": false }
```

- 当全局设置关闭时，返回 `accepted: false`，不入队、不生成 AI 产物。
- 当请求合法但题目已缓存、重复请求、短时间内被限流时，可以静默接受并避免重复入队；前端不展示这些差异。
- 没有合法答题会话、越权题目、题目不属于该会话或考试项目时，返回 403/404；前端 catch 后静默忽略。

### 预热范围与优先级

- 第一版只预热当前题 + 下一题，不扩大到 N 题。
- 同一次预热中，当前题优先，其次下一题。
- 同一题内，翻译优先于 AI 解析。
- 预热生成翻译和 AI 解析两类产物。
- 每个 AI 产物一个后台任务：当前题翻译、当前题解析、下一题翻译、下一题解析最多 4 个任务。

### 后台任务与缓存

- 预热接入现有 `BackgroundJob` / worker 队列。
- 预热任务类型命名为 `ai_prewarm`。
- `ai_prewarm` payload 使用以下字段区分执行内容：
  - `artifact_type`: `"translation" | "explanation"`
  - `exam_id`
  - `question_id`
  - `session_id`
- 预热任务是内部任务，不出现在用户或管理员可见的任务/导入记录页面。
- 预热结果直接写入现有题目缓存字段，供现有按钮复用；不要引入第二套预热缓存。
- 翻译预热复用现有翻译写入路径，写入 `content_zh` 和选项 `text_zh`。
- AI 解析预热复用现有解析写入路径，写入现有解析字段。
- worker 执行预热任务前必须重新检查系统开关和题目缓存状态。
- 如果执行时开关已关闭，或缓存已经存在，worker 应跳过 AI 调用。
- 不做强一致锁；只做缓存复查和轻量去重，接受极少量重复 AI 调用。
- 快速连续切题时不取消已入队预热任务。
- 预热失败只做后端内部记录，不进入用户可见错误提示、toast 或任务列表。
- 成功路径不记录每次成功的详细日志；异常路径记录日志，避免高频噪音。

### 去重与限流

- 预热去重粒度为 `exam_id + question_id + artifact_type`。
- 翻译和 AI 解析分别去重。
- 后端需要做轻量限流：同一用户同一会话短时间内重复请求只静默接受但不重复入队。
- 不新增专门持久化表。
- 可以复用现有 `BackgroundJob` 查询近期 pending/running job 来避免重复。
- 也可以使用可丢弃的短期内存去重作为补充；不能依赖其高可靠性。
- 前端在 `QuizView` 生命周期内做非常轻量的本地去重，记住已触发过的 `session_id + question_ids` 组合；刷新后不保留，由后端继续兜底。

## Acceptance Criteria

- [ ] 管理员系统设置页出现“答题设置”分组，包含“是否启用答题预热”开关。
- [ ] `GET /api/settings/quiz` 返回 `{ quiz_ai_prewarm_enabled: boolean }`，缺省为 `true`。
- [ ] `PUT /api/settings/quiz` 可保存 `quiz_ai_prewarm_enabled`，并写入 `SystemSetting` key `quiz_ai_prewarm_enabled`。
- [ ] `POST /api/ai/prewarm` 接收 `session_id` 和 `question_ids`。
- [ ] 设置开启且请求合法时，进入题目会静默请求预热，后台为当前题和下一题按优先级创建 `ai_prewarm` 内部任务。
- [ ] 设置关闭时，`POST /api/ai/prewarm` 返回 `accepted: false`，不入队。
- [ ] 已缓存的翻译或 AI 解析不会重复生成。
- [ ] 短时间重复触发不会重复入队同一 `exam_id + question_id + artifact_type`。
- [ ] 非法会话、越权题目、题目不属于会话或考试项目时返回 403/404。
- [ ] 预热成功后，再点击“翻译”或“AI 解析”能复用现有缓存并保持现有展示路径。
- [ ] 预热未完成时，点击按钮仍走现有同步生成逻辑并显示现有 loading。
- [ ] 预热失败不会在答题页显示 toast、状态文案或额外 UI。
- [ ] 预热任务不出现在用户或管理员可见的任务/导入记录页面。
- [ ] 前端构建通过。
- [ ] 后端相关测试或手工验证覆盖设置开关、合法预热、关闭不入队、越权拒绝、重复不重复入队。

## Technical Approach

- 后端新增 quiz settings 读写接口，继续使用现有 `SystemSetting` 存储。
- 后端在 AI 路由中新增 `POST /api/ai/prewarm`，依赖当前用户、考试项目上下文和答题会话校验。
- 预热接口只负责校验、设置判断、缓存判断、轻量去重和入队；不在请求线程内调用 AI。
- worker 新增 `ai_prewarm` 处理逻辑，执行前重新读取设置和题目缓存，再调用现有 `translate_question` / `explain_question` 写入同一套缓存字段。
- 前端 `QuizView` 在当前题变化或会话恢复后，基于当前 index 计算当前题和下一题 ID，静默调用 `POST /api/ai/prewarm`。
- 前端不读取系统设置，不展示预热状态，不改变 `TranslateButton` / `ExplainButton` 的交互。
- 管理员系统设置页新增“答题设置”分组，通过 `GET/PUT /api/settings/quiz` 管理开关。

## Decision (ADR-lite)

**Context**: 答题时用户经常在点击“翻译”或“AI 解析”后等待 AI 调用完成。答题过程有天然停留时间，可以利用用户答当前题的时间提前生成可缓存 AI 产物，但这会增加 AI 成本和 worker 压力。

**Decision**: 实现全局可开关的、答题页静默触发的题目 AI 产物预热。第一版只预热当前题和下一题，使用 `POST /api/ai/prewarm` 入队 `ai_prewarm` 内部任务，每个 AI 产物一个任务。预热结果写入现有题目缓存；按钮仍使用现有同步接口和展示逻辑。

**Consequences**: 方案最大化复用现有缓存和按钮行为，避免新增用户可见复杂度；代价是可能有少量额外 AI 调用，且不追求强一致去重。系统设置默认开启，但管理员可全局关闭以控制成本。

## Out of Scope

- 不展示预热状态、进度、成功或失败提示。
- 不改变现有“翻译”和“AI 解析”按钮文案、loading 语义或用户操作路径。
- 不预热超过当前题 + 下一题的题目。
- 不做强一致分布式锁。
- 不新增专门持久化去重表。
- 不做预热命中率、等待时间节省或 AI 成本可视化统计。
- 不创建 ADR。
- 不把预热任务加入用户或管理员可见任务列表。

## Technical Notes

- 领域词表已包含“题目 AI 产物预热”：用户答题期间提前生成当前题或临近题目的翻译、AI 解析等可缓存 AI 产物。
- 现有 AI 同步接口已具备缓存判断：翻译已有缓存时返回缓存，否则生成并写入题目字段；AI 解析同理。
- 现有前端按钮行为应保留：`TranslateButton` / `ExplainButton` 在缓存缺失时调用同步接口并显示 loading。
- 现有系统设置通过 `SystemSetting` key/value 存储。
- 该任务触及跨层契约、API、后台任务和系统设置，完成后必须更新 `.trellis/spec`，并覆盖 7 节 code-spec 深度。
