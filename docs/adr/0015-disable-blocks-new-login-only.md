# 停用账号与重置密码都不吊销已签发的 token

`is_active=false` 只在登录时拦截，不会让已经签发的 JWT 失效；重置密码同理。旧会话最长可用到 token 过期，当前 `ACCESS_TOKEN_EXPIRE_MINUTES=10080`（7 天）。

实现成本决定这个取舍：JWT 是无状态的，要让旧会话立刻失效，就得引入 `token_version` 并在 `get_current_user` 中比对，或改短有效期逼迫重新登录。选择「只拦新登录」保持了现有鉴权链不变，`get_current_user` 也不必每请求判断账号状态。

必须记住后果：**重置密码不能驱赶疑似被盗的会话**。真遇到盗号，唯一立即生效的手段是更换 `JWT_SECRET_KEY`，这会让所有用户一起掉线。若哪天需要「改密码即踢出其他设备」，就得改成 `token_version` 方案，而不是在这里调小有效期。

管理员保护规则中「至少保留一个可用管理员」的判定依赖「可用」= `is_admin and is_active`，被停用管理员的旧 token 仍能调用管理接口，正是这条规则真正会触发的场景。
