## 改动前已核对的仓库事实

1. 后端为 FastAPI、SQLAlchemy，词汇路由在 `backend/app/api/routes/vocab.py`。
2. 普通词已有 `_visible_vocab_query`；高频词通过 `get_bank_in_exam_or_404` 校验题库项目归属，词排除独立存储。
3. 两种 progress 接口现在都是“查询、不存在则插入、commit”，没有首次并发插入的竞争处理。
4. 普通列表会读取整行并分页；学习快照不能直接复用这条读取路径，否则会携带整本释义。
5. `frontend/src/views/VocabularyView.vue` 同时承担概览入口、三个管理列表、添加删除和批量翻译。
6. `frontend/src/api/client.js` 总是覆盖项目头，也从当前存储取 token。学习请求必须固定发送身份并防止旧响应影响新账号。
7. `App.vue` 总是渲染已登录用户的全局导航，并预留移动导航空间；学习页需要路由元信息与媒体查询协同修改。
8. `ExamSwitcher.vue` 在导航之前调用 `examStore.switchTo`。仅增加学习页离开路由守卫不足以保证“先等待保存，再换上下文”。
9. 现有词汇浏览器测试使用真实 Vue 与 HTTP fixture，但不是完整应用路由外壳；缺少学习状态、真实 IndexedDB、锁交接与测试后端闭环。
10. 环境具备 `agent-browser` 和 PostgreSQL 16，探测时 PostgreSQL 端口 5433 可连接。尚未证明已具备专用隔离测试库，不使用现有业务库执行建表或清理。

## 模块边界

### 后端查询与写入

- 新增集中词汇查询服务，例如 `backend/app/services/vocab_query_service.py`：统一授权后的集合、排序、快照与批量可用性读取。
- 在现有 `backend/app/schemas/vocab.py` 声明严格请求和响应结构；现有路由只负责依赖、校验与委托。
- 复用真实所有者／来源／题库可见性规则，必要时把现有普通可见性查询移入共享查询服务。避免复制两套授权条件。
- 快照只 SELECT 身份、必要排序字段与当前用户掌握，不读取释义，不逐词查。
- 内容批读和轻量核验分别选择列，统一保持请求顺序。没有内容的核验不能先读取全文再丢掉。
- 在现有 progress 写入中增加事务内 savepoint，精准处理目标唯一键冲突；非目标约束异常继续抛出。

### 前端学习模块

- `frontend/src/features/vocabularyStudy/`：一个公开学习 Module，以及词汇 HTTP Adapter、续学 Adapter；三来源只改变身份，不复制状态机。
- Module 提供开始／恢复、翻面、前后导航、绝对布尔判定、小结核验、再练／补学、离开和订阅状态。
- UI 不构造词身份、不拼接 API 地址、不访问 IndexedDB；单卡组件只显示文本和发出意图。
- 内容调度集中处理批大小 20、预取余量 5、并发上限 2、身份去重和正文 LRU 上限 100。前台请求优先于后台核验。
- manifest 固定成员和相对顺序；checkpoint 记录本轮结果、位置、不可用集合、阶段及 pending 操作；正文和认证凭据不落盘。
- 保存前冻结账号、URL 项目标识、项目／题库稳定身份、轮次、词与操作标识。发送和消费响应都验证生命周期，不重放恢复历史判断。

### 界面与兼容管理

- 原 `VocabularyView.vue` 保留管理行为为独立展示层；默认路由改为三来源概览，`mode=manage` 与明确来源参数进入管理。
- 新增 `VocabularyStudyView.vue` 和无业务 I/O 的卡片组件，路由为 `/exams/:examSlug/vocab/study`。
- 复用现有按钮、图标、对话框、颜色与暗色主题。通过 route meta 控制学习沉浸，不加入原型开关。
- 无效学习来源、范围或题库参数显式报错，保留返回来源和管理入口；不会静默换词库或范围。
