# 多模型 AI 解析设计（Issue #54）

- 关联：[GitHub Issue #54](https://github.com/longzhuzhu/quiz-app/issues/54)。
- 状态：用户已确认并授权实现的设计规格；实现和验收结果以代码与验证记录为准。
- 日期：2026-10-12。
- 代码核查基线：`98d07214ed765bce07af0734cee3403dad5b88d1`。访谈期间工作区已有其他改动，本次只新增本文，不修改业务代码。
- 决策来源：用户确认 Q1～Q21，并授权剩余细节采用推荐决策，不再继续逐项拷问。

## 1. 问题与目标

题库保存的正确答案不一定可靠。备考人需要对照不同模型独立得出的答案及分析，自行判断，而不是让多个模型共同解释为什么题库答案正确。

本次将单份 AI 解析升级为按模型 ID 区分的多份结果：

1. 管理员配置全站统一的解析模型列表，共用现有接入地址和密钥。
2. 每个模型独立判断、独立生成、独立保存、独立展示和更新。
3. 答案区保留“正确答案”，并新增“AI 推荐答案”汇总。
4. 桌面支持卡片并排，移动端通过模型 Tab 阅读。
5. 全模型预热与手动请求共享去重和并发控制，先完成的模型先展示。

成功标准不是“多个模型一致”，而是结果来源明确、分歧可见、部分失败互不拖累、并发重复请求被合并，也不会将过期解析写回已修改的题目。

本次不是单纯复制前端卡片。前台每模型请求负责创建或复用任务，不再各自绕过后台限制直连上游；轮询只读状态，不触发生成。

## 4. 领域语义与范围

- **正确答案**仍是题库保存的判分依据，沿用现有 `CONTEXT.md` 的定义。
- **模型认定答案**是模型根据题干、选项和题型独立给出的答案；“AI 推荐答案”只是它在汇总区的用户文案，不引入第二种答案来源。
- **答案冲突**表示某模型认定答案与当前正确答案不一致，不等于模型调用失败。
- 不同模型之间可以不一致；不生成多数票答案、权威排名或无依据的置信度。
- 新解析继续包含题干拆解、知识点解释、逐项干扰项分析。不要因改为多模型而删掉既有解析组成。
- 本次覆盖普通练习、专项练习、错题练习所复用的答题卡，以及错题本现有详情入口。
- 模拟考试作答过程隐藏正确答案、推荐答案及解析；不新增模拟考试结果页、题目管理页的解析入口。
- 其他 AI 场景，例如翻译、词汇提取、导入和考点打标，不扩展为多模型，不统一改写其重试和并发策略。

## 5. 管理员配置

### 5.1 有序模型列表

新增解析模型列表 `ai_explain_models`，每项包含：

- `model_id`：去除首尾空白后的非空字符串，保留大小写；按完整 ID 精确去重，不把不同大小写强行合并。
- `reasoning_effort`：未设置时继承默认 `xhigh`；显式字符串表示管理员配置的强度；显式 `null` 表示不发送。

配置允许 1～5 项，支持增删和调整顺序。空项、重复项或超过上限应阻止保存并指出具体原因，不能静默丢弃。高级推理设置与模型 ID 同项维护，不暴露给普通用户修改。

沿用 `SystemSetting` 保存配置，不增加供应商凭据实体。默认模型和翻译模型的配置及回退规则保持原状。

### 5.2 单模型兼容

未设置新列表的存量部署，按原 `ai_explain_model`、再回退 `ai_model` 得到一个有效解析模型，避免升级后变成无模型可用。管理员首次保存新列表后，以新列表为准；设置页面不同时提供两套互相冲突的解析模型编辑入口。

卡片标题使用发起请求的配置模型 ID。历史无来源文本不能贴上这个 ID；网关别名也不被包装为已验证的底层模型身份。

普通用户只能读取有效模型 ID 和顺序，不能通过该读取接口获取密钥、地址或更改推理参数。生成请求中的模型 ID 必须在后端配置白名单内。

### 5.3 配置变更边界

- 重排模型只改显示顺序，不重算。
- 移除模型后不再新建该模型任务，已有结果保留但隐藏；已经接收的任务允许完成并保存，结果仍隐藏。
- 重新加入同一 ID 时，可复用该题仍有效的最近成功结果。
- 修改同一 ID 的推理参数、接入配置或考试项目提示词，不让已保存结果失效，不显示配置过期标记，不自动重新计算。
- 不建设配置快照历史或配置版本浏览。单次执行开始时固定本次调用参数，格式修复使用相同参数，防止一次生成内部切换模型；这不构成配置变更检测功能。

## 6. 结果持久化与有效性

### 6.1 每模型最新结果

增加题目 AI 解析结果记录，以 `(question_id, model_id)` 唯一标识，每项仅保存最近一次成功结果；题目删除时关联结果一并删除。至少包含：

| 信息 | 用途 |
| --- | --- |
| 题目与模型 ID | 结果归属及独立写入 |
| 题目输入指纹 | 防止旧题结果回写或被复用 |
| 规范化 `judged_answer` | 答案汇总与冲突比较，不再从中文文本正则提取 |
| 解析正文及既有结构化分析 | 展示知识点、题干拆解与干扰项分析 |
| 成功生成时间、生成任务标识 | 标明结果时间，识别前端需要重新加载的结果 |

结果必须在校验合格后原子替换。任务状态与成功结果分开表达：存在旧结果的同时，允许处于“排队中”“更新中”或“更新失败”。不能把排队、空响应或错误信息写成成功解析。

旧成功结果在更新期间继续显示；单个模型成功即替换该模型结果，不等待整组事务。其他模型失败不回滚已成功结果。每张卡片的生成时间和更新状态用于区分新旧批次，不声称“更新全部”是同一瞬间的联合结论。

### 6.2 输入指纹与迟到结果

指纹覆盖实际决定题意的输入：题干原文、题型、选项 key、选项原文及顺序。它不包含正确答案、中文翻译、题目排序元数据或 AI 配置；翻译预热写入 `text_zh` 不能导致解析失效。

生成开始时记录输入指纹，保存时在事务保护下重新核对题目输入及任务执行资格。题目删除、输入变化、任务已失败或被作废时，不得写回结果；简单在网络调用前后各读一次、却不保护最终写入，不能算完成并发保护。

发现旧输入结果时将本次任务终结并提示题目已变化，不因收到旧结果而自动追加生成；新题通过正常预热或手动入口生成。数据库事务不得跨越等待上游模型的整个过程。

### 6.3 更正答案与历史数据

- 仅修改正确答案，无论来自答题卡更正还是题目管理编辑，都保留新格式解析。
- 冲突标记由规范化模型答案与当前正确答案实时比较，不将题库答案永久拼进新解析正文。
- 更正答案的确认流程、当前会话重算范围、错题本和其他会话不重算的规则保持原状。
- 更正入口不自动采用首个模型或多数票答案；默认基于当前正确答案，由用户明确选择并确认。
- 题干、选项原文或题型变化时，全部模型结果和旧解析按影响范围失效；不同模型不能各自沿用旧题内容。
- 现有 `Question.explanation`、`Question.explanation_zh` 作为来源未知的历史内容保留，不复制到任何具名模型记录。
- 历史内容单独折叠展示，不推测其模型或推荐答案。新生成只写新结果记录，不同时覆盖历史文本。
- 仅更正答案时仍清空旧文本，避免旧文本里的冲突提示继续指向过期题库答案。
- “不做历史版本”指不保留某模型历次成功正文；保留升级前未知来源内容、移除模型的最近结果或任务执行状态，不构成版本浏览功能。

## 7. 生成、预热和并发

### 7.1 共用生成路径

由一个解析生成模块向调用方提供小接口：读取结果状态、确保有结果、请求更新。模型配置解析、权限检查后的题目输入、去重、任务状态和合格结果替换在同一模块收口，路由与 worker 不各写一套判定。

活跃任务去重范围为考试项目、题目、模型 ID、题目输入指纹。`force` 和请求来源不进入去重键，因此预热、主动查看、更新全部、单卡更新以及跨标签页重复操作可以复用同一活跃任务。组合键应编码或摘要化，避免任意模型 ID 中的分隔符产生碰撞。

| 请求情形 | 行为 |
| --- | --- |
| 已有有效结果，普通查看或预热 | 返回或复用结果，不调用上游。 |
| 缺结果，无活跃任务 | 创建一个生成任务。 |
| 已有排队或运行任务 | 复用任务；手动请求可提升尚未运行任务的优先级。 |
| 已有结果，主动更新，无活跃任务 | 创建更新任务，保留旧结果直到成功替换。 |
| 失败后用户主动重试 | 新建任务，不复用已终结的失败任务。 |
| 失败后重复静默预热 | 不自动重开同题、同模型、同输入的失败任务；等待用户主动重试。 |

最后一条防止“任务没有自动重试，但每次切题又偷偷重新预热”绕过 Q21。题目输入改变后属于新的生成范围，不受旧输入失败记录阻止。

### 7.2 全模型预热

沿用预热开关及当前题、下一题的范围。开启时，为每道题的全部有效配置模型补齐缺失结果，最多涉及 10 个解析任务；已有结果和活跃任务复用。翻译仍按原规则生成一份，不复制成每模型一份。

预热关闭时，不后台生成解析；用户主动查看时仍能按模型并行补齐缺失结果。提交答案不等待模型，也不因为预热关闭而暗中启动全模型调用。

模拟考试的现有后台预热行为不借本次改写；无论是否已缓存，作答响应和作答 UI 都不能展示推荐答案或解析。

### 7.3 两层并发与优先级

- 前端每个页面最多同时发送 3 个模型生成请求，剩余按配置顺序排队；使用独立结果处理，不采用一处失败导致整组失败的交互。
- 创建任务的 HTTP 并发与真实模型调用并发不是一回事；短请求返回排队状态后，不代表模型已经运行。
- 后端设置独立的解析并发额度，默认 3，手动和预热共用；采用部署级配置，不增加普通用户设置入口。额度必须跨 worker 进程共享，不能只使用进程内锁或分别在两条路径限制为 3。
- 解析任务领取与额度获取必须协调；worker 数量和通用 worker 并发不能被误认为该额度。额度不足应排队，不占住其他类型任务的执行位置空等。
- 人工请求优先于静默预热；相同优先级按入队顺序执行；已运行任务不中断。此优先级调整只作用于解析调度，不借机重构其他后台业务的策略。
- 配额只限制应用掌握的在途解析调用。请求超时后上游是否仍在计算，取决于上游服务，不能承诺远端立即停止或绝不计费。

### 7.4 失败、格式修复与中断

- 网络错误、超时、上游 HTTP 错误直接结束该模型任务，不自动重试、换模型或降级推理强度。
- 仅模型返回内容不符合输出结构时，允许最多一次修复调用，仍使用相同模型和调用参数；两次均不合格则失败。
- 空答案、未知选项、单选返回多项均不合格；模型和题库答案不同是合格结果，不因分歧触发修复。
- 单个任务最多一次正常调用加一次格式修复，不允许外层 worker 默认重试将其放大为多轮。
- worker 中断导致执行结果不确定时，该解析任务应终结为可手动重试的失败，不套用通用任务自动恢复重跑规则；已经开始过的上游调用无法保证恰好一次计费。
- 失去执行资格的旧 worker 不能在恢复后覆盖新结果。任务资格检查和结果提交必须原子协调。
- 已被后端接收的任务在切题、关页后继续；页面停止轮询并丢弃迟到响应，尚未提交的前端排队请求停止发送。

## 8. 后端接口与模块职责

### 8.1 接口行为

在现有 AI 路由内扩展，不创建第二套模型接入系统：

| 接口 | 目标行为 |
| --- | --- |
| `GET /api/ai/explanation-models` | 返回当前用户可用的有序模型 ID 列表，不返回连接密钥等管理员配置。 |
| `GET /api/ai/explanations?question_id=...` | 读取该题轻量汇总：每模型最近成功答案、生成时间、结果标识、当前任务状态和安全错误信息。只读，不生成。 |
| `GET /api/ai/explanation?question_id=...&model_id=...` | 读取一个模型完整结果和当前状态；模型 ID 用查询参数承载，兼容包含 `/` 的 ID。 |
| `POST /api/ai/explain` | 接受 `question_id`、`model_id`、`force`；只操作一个模型；缓存命中返回 `200`，创建或复用活跃任务返回 `202`。 |
| `POST /api/ai/prewarm` | 保持当前会话和题目归属验证；后台按配置列表创建或复用每模型任务。 |

生成响应明确区分最近成功 `result` 与当前 `generation`；存在旧结果不代表更新已完成。无结果、排队、生成中、失败和成功应能被前端无歧义识别，不能用 `cached` 一个布尔值承担所有状态。

前端“更新全部”按当前列表分别发出 `force: true` 请求，不增加后端等待全部完成的聚合生成调用。“单卡更新”仅发送该模型请求。普通查看使用 `force: false`，有结果先显示、缺失结果再补齐。

### 8.2 权限和数据隔离

- 所有读取、生成、状态查询均验证登录、考试项目归属和题目归属，不因知道 job ID 或 question ID 获得额外权限。
- 普通用户无法通过请求体指定任意未配置模型、推理参数、URL 或 API Key。
- 继续沿用管理员对他人项目只读、不能生成或更正的现有权限边界，不通过新增状态接口扩大权限。
- 不向普通客户端返回通用 job 的原始 payload、上游完整异常、连接配置或密钥。
- 不直接放开现有通用 `/api/jobs` 白名单；由题目解析的受控读取接口返回最小状态投影。

### 8.3 兼容与传输成本

新客户端必须处理 `202` 和逐模型状态；这不是仅在原同步响应上增加字段，前后端应配套部署。旧标签页不承诺无缝处理新协议，部署后需要刷新；不能为旧调用保留一条绕过并发和去重的同步直调路径。

练习开始、恢复和错题列表只携带展示所需轻量汇总，不把每题最多 5 份长解析塞入整场题目载荷。后端批量读取汇总，避免逐题逐模型查询。当前题或展开的错题再加载正文；状态轮询使用轻量汇总，只在成功结果标识变化时重取对应正文。

## 9. 前端交互

### 9.1 答案区

保留“正确答案”，其下增加独立的“AI 推荐答案”区域，例如：

```text
正确答案：D

AI 推荐答案
model-a：D
model-b：D
model-c：A（与题库答案不同）
```

模型顺序固定为管理员配置顺序，不按返回速度或答案一致性排序。多选显示规范化选项集合，例如 `A,C`；比较采用选项集合语义，不能因 `C,A` 与 `A,C` 的文本顺序不同标记冲突。

没有成功结果时显示“未生成”“排队中”“生成中”或“生成失败”，不填假的答案。更新中继续显示旧答案并注明状态；失败时显示“更新失败，当前显示上次结果”。点击某模型答案定位对应卡片或 Tab，不自动触发更正答案。

普通练习未提交时，预热完成不能自动展开推荐答案；主动点击 AI 解析可以提前查看。提交后展示已有汇总和正文，仍在运行的模型完成后独立补上，不阻塞提交、切题或计时。预热关闭且尚无任务时如实显示未生成，等待用户主动查看。

错题本的折叠摘要显示已有答案汇总，但不因加载整个错题列表而为所有错题批量生成。展开详情展示已有正文，用户使用既有 AI 解析入口补齐缺失结果或更新。

### 9.2 卡片与操作

- 卡片标题为模型 ID，附生成时间、状态及与题库答案的冲突提示；长 ID 允许换行或提供可访问的完整名称。
- 保留原“AI 解析／更新解析”的整体入口，文案明确为“更新全部解析”。“更新解析”始终更新全部当前配置模型，而不是只更新当前移动 Tab。
- 每张卡片标题行右侧提供单模型更新图标：更新中旋转并禁用重复点击，成功或失败后恢复静态；可访问名称区分“生成／更新／重试 <模型 ID>”，失败提示与旧解析保留。
- 运行中的操作显示状态，阻止重复点击制造重复请求；即使其他标签页提交重复请求，后端仍须去重。
- 全部更新是分别完成，不遮罩整个答题页。仍可查看旧结果、切换模型和切题。
- 旧解析单独折叠展示，不占用一个具名模型的 Tab，不进入答案汇总。

### 9.3 响应式和可访问性

桌面根据解析区域实际可用宽度而非仅视口宽度排版：卡片最小阅读宽度以约 320 px 为设计起点，通常 2 列、足够宽时 3 列；最多 3 列，其余换行，空间不足退为 1 列。不得为容纳 5 个模型制造整页横向滚动。

移动端使用模型 Tab，正文仅渲染当前激活模型。所有模型的答案与任务状态仍在汇总区可见；Tab 数量较多时仅 Tab 条可横向滚动。支持键盘切换、焦点状态和辅助技术的标签关联，长正文不被底部导航遮挡。

2026-10-13 展示调整（用户已确认）：移动端取消正文内部限高和纵向滚动，完整展开并随页面滚动；桌面保留正文内部滚动。按模型配置顺序使用蓝、紫、绿、橙、玫红五套底色与边框，卡片、标题、更新按钮及对应 Tab 共用模型配色，适配深色模式；生成状态与错误仍以明确文案呈现，不以模型颜色代表正确性。

2026-10-13 选择条与单卡操作调整（用户已确认）：模型选择条在移动端与桌面端使用同一视觉——淡背景加 2 px 下划线表示选中，取消原有深色粗外框；桌面仍并排比较全部卡片，移动端仍只渲染当前激活模型；无障碍语义按端区分（桌面 `role="group"` + `aria-pressed` 并全部可 Tab 聚焦，移动端保留 `tablist` + roving tabindex）。单模型更新改为标题行右侧刷新图标，见 9.2。

模型完成不自动切换 Tab，不抢焦点；当前题内切换模型应保留可用的阅读位置。切题后默认首个配置模型，所有迟到响应按题目及模型归属处理，不能把上一题内容写入当前卡片。

## 11. 验收与回归要求

### 11.1 配置和单模型兼容

1. 仅有旧单模型设置的部署仍有一个可用解析模型；列表可配置 1～5 项，重复、空项和第 6 项被拒绝。
2. 列表顺序在桌面、Tab、汇总及刷新后稳定一致；普通用户不能修改配置或获取凭据。
3. 未配置推理强度发送 `xhigh`，显式覆盖按原值发送，显式不发送不带该字段；不支持参数的模型失败但不会被自动换掉。
4. 调整同 ID 的参数不自动失效或重算旧结果；模型增删和重排遵守 Q10。

### 11.2 结果与可信度

5. 三模型返回 `D / D / A` 时，汇总与卡片一一对应；只标记与题库答案的分歧，不自动裁决或改判。
6. 单选、判断、多选及非 A～D 的合法选项均正确处理；空答案、非法选项和单选多项输出不进入成功结果。
7. 模型提示词不包含题库正确答案或其他模型答案；题型明确传入；输出修复也不得泄露这些答案。
8. 历史解析可继续阅读，但没有被伪造模型身份或加入推荐答案汇总。
9. 每模型只留最近成功结果；更新失败保留原正文、答案和时间，不被半成品覆盖。

### 11.3 并发与后台执行

10. 前端最多 3 个并行生成请求；不同模型独立成功或失败，不等待最慢模型才显示。
11. 全模型预热覆盖当前题及下一题，缓存命中不调用上游；翻译不按模型数重复生成。
12. 预热、单卡更新、更新全部、多个标签页同时命中同一生成范围，只创建一个活跃任务；任务结束后主动更新才产生新任务。
13. 多进程 worker 下默认最多 3 个应用侧在途解析调用；手动和预热共享额度，其他类型任务未被错误限为 3。
14. 手动请求可提升复用的排队任务优先级，但不重复入队，也不打断已运行任务。
15. 网络和上游错误不自动重试；输出格式最多修复一次；外层 worker 和后续静默预热均不能绕过这一限制。
16. 切题或关页后，已接收任务继续，未提交请求停止；再次打开可读已保存结果，旧响应不污染当前题。
17. worker 中断、任务失效和迟到结果有明确终态；不能自动重跑不确定的上游调用，不能让旧执行者覆盖新结果。

### 11.4 编辑、隔离与页面回归

18. 仅更正正确答案保留新解析并重算冲突；题干、选项原文或题型修改使解析失效，运行中的旧输入结果不能写回。
19. 翻译填入 `content_zh/text_zh` 不使解析失效，也不重复触发解析；删除题目后旧任务不能重新创建其结果。
20. 非所有者不能查询、生成或更新他人题目解析；移除模型不再接受新调用；错误响应不泄露密钥和上游敏感信息。
21. 普通练习未作答时无自动剧透，主动查看仍可用；提交不等待 AI；模拟考试作答期间无新增答案泄露。
22. 错题列表显示轻量汇总，不随列表载入批量生成或传输全部长解析；模拟考试结果页和题目管理页未增加入口。
23. 375 px、768 px、1280 px、宽桌面及明暗主题下验证布局；5 模型、长 ID、长解析、部分失败均可读，无整页横向溢出或底部导航遮挡。
24. 移动端 Tab、键盘与辅助技术可用；异步完成不抢焦点或切换模型；原提交、更正、计时、切题和词汇操作不回归。

优先扩展现有 `backend/tests/test_ai_explanation_refresh.py`、`test_correct_answer.py`、`test_ai_reasoning_effort.py` 等行为测试，并围绕共用生成模块及公开接口补充数据库并发测试。前端使用既有 Node 测试和真实浏览器验证；并发唯一性、事务保护和跨 worker 配额必须在 PostgreSQL 上验证，不能只以进程内 mock 通过代替。

实现后运行相关后端回归、前端 `npm test`、`npm run build` 及上述多端关键流程。本次为文档工作，仅做文档一致性和引用检查，不声称功能测试已经通过。

## 12. 上线约束与非目标

上线需配套完成数据库迁移、后端、前端和 worker 更新，并同步第 10 节文档。旧 worker 不得继续按单结果路径写入；部署时先停止接收旧解析任务并等待或终结旧任务，再切换新生成路径。回滚前须核实新结果记录和旧字段的兼容性，不自动把某一个新模型结果冒充为全部解析。

本次不包含：用户自带密钥、多供应商凭据、项目自选模型、模型投票、自动纠错或改判、“无法判断”结果、结果历史浏览、配置变更检测、配置快照版本管理、全库自动重算、流式逐字输出、新消息中间件或新模型网关。

用户已授权开始实现。本文件是设计规格，不是逐文件执行计划；实现须覆盖存储与迁移、共用生成路径、前端展示和回归验证，不能以“界面多放几张卡片”替代并发与数据一致性工作。
