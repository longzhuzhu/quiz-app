# 当前题计时规格（Issue #53，收窄版）

## Problem Statement

答题用户无法在当前题目旁看到作答用时，也没有可用于后续每题耗时统计的答题记录。用户需要一个轻量的单题秒表，并在提交答案时保存首次成功提交的耗时；当前不需要整场计时、统计页面或跨设备同步。

本规格取代原先的整场与单题持久化计时方案，以本次重新访谈确认的范围为准。

## Solution

全部五种答题模式在答题页仅展示当前题正计时。当前题加载完成且页面可见后自动开始；切题暂停上一题，在同一次页面使用中返回该题时接着累计。

切后台暂停，回到页面续计；首次提交答案成功后停止，随后看解析或改答不再计时。未提交的计时状态仅保存在本次答题页面内存中，刷新或重新进入页面不保留。提交答案时携带本题耗时，与答案一起保存，后续改答不覆盖首次耗时。

刷新后进入已提交题目，仍只显示「已提交」，不恢复秒表。不记录整场用时，不在结果页或历史记录展示计时；后端仅扩展现有答案提交与答题记录，不增加独立计时或同步接口。

## User Stories

1. 作为答题用户，我希望顺序练习展示当前题用时，以便了解作答节奏。
2. 作为答题用户，我希望随机练习同样展示当前题用时，以便不同入口体验一致。
3. 作为答题用户，我希望模拟考试使用同样的正计时，以便观察用时但不被限时规则打断。
4. 作为答题用户，我希望错题练习展示当前题用时，以便观察错题的作答耗时。
5. 作为答题用户，我希望专项练习也展示当前题用时，以便了解针对考点练习的节奏。
6. 作为答题用户，我希望题目加载完成且页面可见后自动开始，以便不需要额外操作，也不把初始加载等待计入。
7. 作为答题用户，我希望切到其他题目后上一题暂停，以便时间不会归入错误的题目。
8. 作为答题用户，我希望在同一次页面使用中返回未提交题目时续计，以便切题不清零该题已有用时。
9. 作为答题用户，我希望切后台暂停、回到页面续计，以便后台期间不计入当前题用时。
10. 作为答题用户，我希望首次提交成功时计时停止，以便看到该次成功提交携带的本次页面内累计耗时。
11. 作为答题用户，我希望提交失败时仍然计时，以便失败请求不会把题目错误地标记为计时结束。
12. 作为答题用户，我希望提交后阅读解析不再增加用时，以便答题与解析阅读的时间不混在一起。
13. 作为答题用户，我希望已提交题目再次改答时保持停止，以便不引入额外的重答计时规则。
14. 作为答题用户，我希望返回本次页面内已提交题目时仍看到停止时的用时，以便回看不重置或重新启动。
15. 作为答题用户，我希望刷新或重新进入页面后未提交题目从零开始，以便符合不保存计时数据的轻量范围。
16. 作为答题用户，我希望恢复以前已提交的题目时只显示「已提交」，以便系统不伪造已经丢失的用时。
17. 作为答题用户，我希望提交请求期间切题也不会停止另一题的计时，以便异步请求不造成时间归属错误。
18. 作为答题用户，我希望长时间计时的显示不回绕，以便正确理解当前题累计用时。
19. 作为答题用户，我希望计时不会改变判分、改答、自动下一题和模拟考试答案隐藏行为，以便已有答题体验保持稳定。
20. 作为答题用户，我希望提交答案时同时保存本题耗时，以便以后可以统计各题作答耗时。
21. 作为答题用户，我希望后续改答和重复提交不覆盖首次成功提交的耗时，以便首次用时记录稳定。
22. 作为使用旧版客户端的用户，我希望未携带耗时也能正常提交答案，以便新增字段不破坏原有流程。
23. 作为统计数据的使用者，我希望缺失耗时与真实零耗时区分，以便旧数据不会被误算为瞬间作答。
24. 作为统计数据的使用者，我希望记录明确表示本次页面内耗时而非跨刷新完整耗时，以便后续统计不夸大数据完整性。

## Implementation Decisions

- 范围覆盖顺序练习、随机练习、模拟考试、错题练习和专项练习，只显示答题页当前题用时。
- 采用正计时，默认显示到秒，超过一小时不回绕。展示沿用现有答题页布局和明暗主题，不新增控制面板。
- 在当前题已加载、页面可见且题目未提交成功时累计；尚未加载、切走或页面隐藏时不累计。页面重新可见时仅恢复当前未提交题目的计时。
- 同一次答题页面生命周期内，按题目标识保存各题累计值；只展示当前题，不汇总整场。不按题目显示序号归属时间。
- 首次提交成功后固定该题用时，阅读解析、返回和改答均不重启或覆盖这个值。提交失败继续计时，成功判定沿用现有答案接口，包括模拟考试的已提交响应。
- 已确认的保存规则：在首次成功创建本场该题答案记录时保存耗时；同一会话同一道题后续改答、重试和重复提交都不覆盖。首次未提供耗时则保留未知，不能通过后来的改答伪造首次耗时。
- 工程默认口径：每次提交请求发出时取得当前题累计耗时快照；该次请求成功后将页面计时固定在此快照，与保存值一致，不把网络往返等待计入本次成功提交的耗时。请求失败不固定，计时继续，下一次提交重新取快照。这是为了单次答案提交即可保存，避免成功后再发送计时请求。
- 提交请求与其发起时的题目绑定；响应回来时只停止对应题目，不得根据当时界面正在显示的题目操作计时。
- 本次页面内有计时数据的已提交题目显示固定用时；进入页面时已提交但没有本地计时数据的题目只显示「已提交」，不从服务器时间戳推算，不显示假的零用时。
- 未提交的计时状态只在答题页面内存中保存，不使用浏览器持久存储，不进入全局会话持久化状态。刷新、离开后重新进入、更换答题会话时重新初始化。只有提交成功后的耗时快照作为答案记录的一部分持久保存；保存记录不意味着恢复秒表。
- 卸载或更换会话时清理定时器及可见性监听，防止旧题继续计时、监听重复或异步旧响应污染新会话。
- 扩展现有答案提交请求，接受可选的非负整数毫秒耗时；扩展现有答案记录，增加可空耗时字段，并提供相应数据库迁移。不新建计时数据表，不增加独立计时请求，不回填旧记录。
- 耗时与首次答案在同一事务中保存，答案提交失败不能留下成功耗时记录。缺省或空值表示未知，已知零值保留为零；明确非法的类型或负值应被验证拒绝。已有记录的首次耗时（包括未知）在改答时保持不变。
- 保存值按既有会话与题目关联，从会话获得用户归属，沿用所有者、考试项目与题目归属校验。每个页面独立运行，不做多标签页或跨设备互斥与接管。
- 不改变既有答案提交、判分、改答、恢复位置、自动下一题、完成会话及模拟考试答案隐藏规则。

## Testing Decisions

- 前端通过计时模块公开行为与答题页面展示验证。后端仅围绕现有答案提交 API 与数据库重读，补充耗时保存和不被改答覆盖的集成验证；不新增实时计时或多端接管测试。
- 优先沿用已有 Node 原生测试的组织方式，用可控制的时间输入验证外部累计结果，不断言内部字段或定时器调用次数。
- 页面验证覆盖当前题显示、切题返回、首次提交成功和失败、改答不重启、异步提交期间切题、可见性暂停、刷新与离开后重新进入。
- 覆盖恢复后已提交题目仅显示「已提交」，以及本次页面内提交后返回仍显示固定用时。保存快照与成功后页面固定值一致；失败后继续累计，重试成功保存新的提交快照。
- 覆盖更换会话和页面卸载后的隔离与资源清理；新会话不能继承上一会话的计时状态。
- 对五种模式、长时显示、桌面和移动端、明暗主题进行展示验证；计时不得泄露模拟考试答案。
- 答案提交集成测试覆盖五种模式、首次耗时保存、后续改答保留首次值、首次未知不被补写、旧客户端缺省兼容、真实零值、非法输入及提交失败不写入。验证不同会话对同一道题各自独立记录，以及已有权限与题目归属限制。
- 验证迁移后旧记录的耗时为空且原答案不变；不回填时间戳差值。计时新增字段不能改变既有答案计数、判分与练习统计口径。
- 回归已有前端、相关后端测试及构建。仅文档调整不声称已运行或已通过功能测试。

## Out of Scope

- 整场计时、整场汇总，以及本次实现中的每题平均耗时、图表或其他统计分析页面；本次只为后续统计保存基础数据。
- 独立后端计时接口、新计时数据表、未提交过程持久化、实时同步和心跳；仅现有答案记录的耗时字段及其迁移在范围内。
- 刷新、离开、跨天或跨设备恢复用时。
- 结果页、历史列表和历史详情的用时展示。
- 多标签页计时权、跨设备互斥、接管和冲突提示。
- 重答重新计时或累计重答时间。
- 倒计时、限时配置、超时交卷、手动暂停或继续按钮。
- 从创建、完成或最后提交时间推算历史用时。
- 修改练习日、当日作答量、正确率及滚动正确率等现有统计。

## Further Notes

- 关联：[GitHub Issue #53](https://github.com/longzhuzhu/quiz-app/issues/53)。本版本替代之前的复杂计时规格；仅增加首次成功答案提交的耗时保存，不恢复整场计时、未提交过程持久化或多端接管。
- 重新访谈结论：Q1=B（本次页面内按题累计，刷新归零）；Q2=A（首次提交成功停止）；Q3=A（切后台暂停）；Q4=A（改答保持停止）；Q5=A（保存首次成功提交耗时，后续改答不覆盖）。
- 上一版曾将看解析计入用时；这一规则已被本次「提交成功后停止」明确替换，不应混用。
- 全部模式的覆盖范围保留，其余计时范围按本版本收窄。保存用时只反映该次成功请求发出前、本次页面内的可见累计时间，不代表跨刷新完整作答耗时或专注度。后续统计必须明确这一口径，旧数据和缺失值不得按零参与统计。
- 答案仍采用每场每题一条、改答覆盖答案的现有模型；首次耗时固定，因此不能把这个耗时误称为最后一次改答速度，也不新增逐次尝试日志。
- 用户要求停止技术细节访谈，实施时在上述行为约束内选择最小方案，不恢复已删除范围。
- 本轮仅更新规格，不启动代码实施；截至此次更新尚未修改业务代码。
