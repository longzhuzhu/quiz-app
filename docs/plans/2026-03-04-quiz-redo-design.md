# 答题页重答能力设计方案（最后一次作答生效）

日期: 2026-03-04
状态: 已确认

## 背景与问题

当前答题流程存在两个限制：

1. 前端在题目已作答后会禁用选项并隐藏“提交答案”操作。
2. 后端在同一会话同一题目二次提交时直接返回 `该题已作答`。

这会导致用户在确认答案或复盘时无法修改已提交选择，也无法回显并编辑历史选择。

## 目标

在不改变现有页面结构的前提下，实现：

1. 已答题目支持再次选择并重新提交。
2. 成绩统计按“最后一次作答”生效。
3. 已答题目重新进入时可回显当前已选答案。
4. 保持现有接口结构与数据库结构尽量稳定，避免大规模改造。

## 方案选型

### 方案 A（采用）：单条答案记录覆盖更新

- 保持 `quiz_answers` 现有唯一约束（`session_id + question_id`）。
- 首次提交创建答案记录；后续提交更新同一记录。
- 统计字段按旧结果与新结果差量修正。

优点：改动小、兼容现有模型与接口。

### 方案 B：多条尝试记录并实时取最后一条

- 每次提交新增一条记录，统计时取每题最后一条。
- 需要数据库迁移和多处查询重写，复杂度高。

### 方案 C：当前答案与尝试历史分表

- 当前答案表负责查询，历史表负责审计。
- 重构成本高，超出本次需求。

## 详细设计

## 一、后端接口与数据行为

文件：`backend/routes/quiz.py`

### `/api/quiz/answer` 行为调整

- 保留：会话归属校验、会话完成态校验、题目存在校验。
- 移除：遇到已答题即报错的分支。
- 新行为：
  - 若题目首次作答：
    - 新增 `QuizAnswer`
    - `answered_count += 1`
    - 若答对则 `correct_count += 1`
    - 若答错则沿用现有错题本累积逻辑
  - 若题目已存在作答记录：
    - 更新 `user_answer`、`is_correct`、`answered_at`
    - `answered_count` 不变
    - `correct_count` 按旧值与新值做差量修正：
      - 旧错 → 新对：`+1`
      - 旧对 → 新错：`-1`
      - 其他情况：`0`

### 数据模型

文件：`backend/models.py`

- 保留 `QuizAnswer` 唯一约束，不做数据库迁移。
- 通过“更新同一记录”实现“最后一次作答生效”。

### 会话恢复接口

文件：`backend/routes/quiz.py` 的 `session_detail`

- 继续返回 `answers[].user_answer` 与 `is_correct`。
- 因答案记录被覆盖更新，接口天然返回最新结果。

## 二、前端交互与状态管理

文件：`frontend/src/components/QuestionCard.vue`、`frontend/src/views/QuizView.vue`

### QuestionCard 交互调整

- 已答后仍允许点击选项（去掉禁用逻辑）。
- 保持“提交答案”操作可持续使用（用于更新答案）。
- 提交后反馈区按最新提交结果刷新。

### 已答答案回显

- 在题目切换时，不再一律清空选中状态。
- 父组件基于会话详情中的 `answers[].user_answer` 维护 `questionId -> user_answer` 映射。
- 进入题目时将当前题已有答案注入 `QuestionCard`，用于初始化 `selectedAnswers`。

### 导航与统计显示

- 继续使用 `answerResults[index]` 显示正确/错误状态。
- 每次提交后覆盖当前题状态，保持与后端“最后一次作答”一致。

## 三、统计一致性与边界处理

### 统计规则

- `answered_count`：按“是否首次作答该题”计算。
- `correct_count`：按当前题最新答案是否正确计算（通过差量修正实现）。
- 结果页与过程页统计均以最新答案为准。

### 错误与边界

- 保留无权限、会话已结束等错误处理。
- 移除“该题已作答”错误。
- 对 `correct_count` 的扣减做边界防护，避免异常情况下出现负值。

## 四、验证方案

### 后端验证

1. 同题首次提交错误：`answered_count=1, correct_count=0`
2. 同题二次改正确：`answered_count=1, correct_count=1`
3. 同题三次改错误：`answered_count=1, correct_count=0`

### 前端验证

1. 已提交题目可继续修改选项并再次提交。
2. 切题后返回，历史选择可正确回显。
3. 重新提交后反馈区与题号状态实时更新。
4. 全流程不再出现“该题已作答”阻断。

## 非目标

- 不引入“每次尝试历史轨迹”展示能力。
- 不在本次中新增错题自动移除等扩展策略。
